Design — API contract & screen flow

FastAPI exposes 4 endpoints. Frontend drives the two-phase flow.

FastAPI endpoints (backend)

GET /search?q={query} → account/opp matches from Snowflake
GET /lookup?opp_id={id} → full prefill for a specific opp
POST /diagnose → answers{} → diagnosis + session estimate
POST /prose → diagnosis → LLM paragraphs (Anthropic)

All existing Python logic stays unchanged — FastAPI just wraps it. Thin routes, no business logic in main.py.

Two-phase screen flow

PHASE 1 — Self-service (AE)
① Search screen
Opp ID or account name
② Review prefill
MRR, products, Snowflake answers
③ Questionnaire
Remaining questions, step by step
④ Proposal output
Executive overview, objectives,
engagement table, scope, shared
responsibility — copy-paste ready
+ CTA: "Submit TPS request"
PHASE 2 — Deep scope (Architect/Manager)
⑤ Import Phase 1 proposal
Auto-loaded from Phase 1 session
⑥ Choose flow
Pre-made modules (EMEA)
or Custom (James / Americas)
⑦ Workstream builder
Sessions per workstream, timeline,
deliverables table
⑧ Full proposal output
Olympus-doc format, export-ready
