Google Auth — how it works in Next.js

NextAuth.js replaces Streamlit's st.login(). Same Google OAuth client, same @datadoghq.com restriction.

What changes vs today

Today (Streamlit)
st.login("google") triggers OAuth
Secrets written to secrets.toml at boot
Session lives in Streamlit's memory
hd=datadoghq.com in client_kwargs
Server-side email check as backup
Next.js (NextAuth.js)
NextAuth handles the OAuth dance
Same Google client ID + secret (Secret Manager)
Session stored as signed JWT cookie
hd=datadoghq.com param still enforced
Server-side email check still in middleware

Auth flow

1. User visits is-scoping-frontend.run.app
    → Next.js middleware checks for session cookie
    → No session → redirect to /api/auth/signin

2. NextAuth redirects to Google OAuth
    → hd=datadoghq.com shows only Datadog accounts

3. Google redirects back to /api/auth/callback/google
    → NextAuth verifies email ends in @datadoghq.com
    → Creates signed JWT session cookie

4. Every page — middleware checks cookie
    → Valid → serve page
    → Invalid/expired → back to step 1

5. Frontend → backend calls
    → Cloud Run service account token (IAM invoker)
    → User email passed in X-User-Email header (audit only)
    → Backend trusts frontend via IAM, not Google OAuth

One change needed in GCP

Add the new frontend URL as an authorised redirect URI on the existing
splunk-dd-google-client-* OAuth client:

https://is-scoping-frontend-[hash].us-central1.run.app/api/auth/callback/google

Same client, no new OAuth app needed. The Streamlit redirect URI stays
in place until the old service is decommissioned.
